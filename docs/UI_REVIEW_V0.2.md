## 修复与体验调整

| 发现                                   | 处理与验收                                                                         |
| -------------------------------------- | ---------------------------------------------------------------------------------- |
| 首页两个全宽演示按钮难以区分           | 改为两张示例卡，说明3桌名单与12桌场地图各自用途；每次独立创建活动                  |
| 首屏摘要过高，工作画布出现太晚         | 缩减概览留白；手机保持四项人数并列；保留完整出席口径和保存时间                     |
| 手机活动按钮挤压重叠                   | 去掉通用标题样式遗留的150px宽度上限，双列等宽排列                                  |
| 平面图未安排组像按钮，却只能拖拽       | 增加点选后选择目标桌、确认整组安排；直接复用原事务服务和撤销链                     |
| 选桌后才发现整组坐不下                 | 点选安排和地图换桌菜单显示余席、锁定、差额；不可用目标禁选；服务仍在写入前重新校验 |
| 手机选中桌位后难找下方名单             | 增加“查看选中项详情与名单”入口，滚动并聚焦详情，尊重减少动画偏好                   |
| 刷新丢失工作视图，两个视图同时呈现主色 | 由URL保存list/floor/board，刷新、返回和前进可恢复；仅当前视图呈选中态              |
| 保存反馈插入文档导致内容跳动           | 改为可关闭的底部状态反馈，错误保留到关闭或下一次操作；不自动吞掉错误               |
| 长弹窗关闭/保存入口滚走                | 弹窗标题与表单底部操作使用粘性布局；保留原生dialog焦点约束与Escape                 |
| 手机输入容易触发自动放大               | 输入、选择和文本框使用16px字号；未安排组允许纵向触摸滚动                           |

容量提示使用新的纯函数tableChoices，按稳定ID逐条生成，绝不合并同名组。它只帮助选择；并发变更仍由service/repository的事务防护决定结果。此次不改变数据模型、备份格式或排桌算法，不引入后端或远程资源。

## 用户截图复查：20桌、零宾客（2026-10-20）

上轮走查漏掉了长桌位列表与空名单并存的状态。固定左右双栏使20桌列表撑高整页，短名单旁留下大片空白；这属于布局问题。

现改为稳定的上下全宽布局：桌位管理在上，全部宾客名单在下。桌位区采用限高原生滚动与固定表头（桌面340px、手机300px），保留全部行与操作，不按人数动态改变布局。空名单显示下一步导入引导；零宾客时不显示无用的名单筛选、批量操作和两桌对调控件。新增第一组后恢复相关工具，人数与数据存储不变。

新增六配置场景覆盖“20桌/0组”→查看末桌→打开导入→添加4人家庭，验证上下排列、面板全宽、桌位区高度、20行完整保留与无页面横向溢出。已有300/500人流程继续验证大量宾客场景。截图位于`output/playwright/list-layout/empty-*.png`，全部虚构。
