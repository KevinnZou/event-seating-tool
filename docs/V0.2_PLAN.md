# V0.2 开发与验收范围

按用户确认的顺序：场地平面图（圆桌自由位置/缩放、舞台入口区域）、可视化整组排桌、SVG/PNG及打印、命名方案/差异、解释型规则建议。保留本地、无账号无后端、整组人数守恒与锁定，不加入V0.3婚礼附加业务。

- 数据：Event内可选venue；Table内可选position。旧数据不填坐标，打开时确定性网格展示，首次布局命令才落库。检查点可选name表示命名方案。
- 迁移：Dexie 2→3无删表或重建ID，阻止旧代码降级写入；新导出协议V2，读取兼容原V1。所有新字段进入快照、历史、复制、检查点和完整备份。
- 场地单位为画布坐标而非测量承诺，不做真实座椅/舞台礼仪。桌位锁定同时保护人数安排和布局位置。
- 重叠提示不擅自移动任何桌，越界命令拒绝。尺寸调整不得裁掉桌位/区域；自动整理只移动未锁定桌并且可撤销。
- SVG/PNG只含场地区域、桌号、占用/容量、总体人数，不含宾客姓名；名单交付继续使用原有报表。XML严格转义，无外部图片或脚本。PNG限制最大边/像素数。
- 命名方案是完整活动快照，显示当前与所选或两个版本的新增/删除/人数/出席/调桌/桌位/布局差异；恢复前创建安全检查点，失败不覆盖，恢复清除不再适用的内存撤销栈。
- 规则建议只针对未安排且出席的整组，提供紧凑/同类优先/均衡规则与解释；不拆分，不触碰已有安排或锁定桌，不通过姓名推断关系。先生成不可写库预览，确认时校验基准快照防并发覆盖，未能安排者逐组解释并保留。
- 每一阶段执行lint/typecheck/tests/build并提交；最后全套双引擎/六设备主流程及生产离线验证。所有测试虚构，不推送部署。
