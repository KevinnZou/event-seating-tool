# V0.2 整体验收

日期：2026-10-20。用户确认的五项范围均已实现：场地平面图、可视化整组排桌、图像/打印交付、命名方案与差异、可解释规则建议。沿用本地IndexedDB，无账号/云端/LLM，不包含V0.3业务。

## 入口与升级

- 当前生产预览：`http://127.0.0.1:4176/event-seating-tool/`。若缓存仍显示V0.1，先下载JSON备份，等待“新版本就绪，备份后刷新”并确认。不要清理站点数据。
- 新用户推荐首页“试用场地平面图演示”：全虚构12张跳号桌，舞台/入口/接待区，120人已安排、2人未安排、1人不参加。它作为新的独立活动创建，不覆盖已有活动。
- 活动卡片直接选择“场地平面图”，或工作区切换同名视图。页面内可切换“安排宾客”“调整布局”；“导出场地图”打开SVG/PNG/横向A4打印交付。
- 活动顶部提供“命名方案与差异”和“规则排桌建议”。原名单导入、列表、桌卡、JSON及Excel报表仍可使用。
- 启动：`npm ci && npm run dev`；生产：`npm run build && npm run preview -- --host 127.0.0.1 --port 4176 --base /event-seating-tool/`。不同端口不共享活动数据，需要JSON显式迁移。

## 一次性验收建议

1. 使用“试用场地平面图演示”，核对12桌、计划122、已排120、未排2；66仅是桌号。切“调整布局”拖动圆桌/区域，或在详情填写坐标，刷新应保留。
2. 另用原“试用虚构演示”，把4人家庭整组排到03桌，人数占4席。尝试超员或锁定桌，操作应阻止；可以撤销/重做。
3. 保存“初稿”，修改人数、调桌、移动圆桌或区域后打开差异；选两个状态核对。恢复初稿后，应能在检查点中找到恢复前状态。
4. 打开规则建议，切换三种规则并检查预览；生成预览时已排人数不变，确认后才写入。对容纳不了的组必须保留并解释。应用后可一步撤销。
5. 导出SVG/PNG/打印图，核对场地区域和人数，图中不应出现宾客姓名；另从原导出页下载完整Excel/文字名单。
6. 下载含方案的完整JSON，默认恢复为新活动，核对位置、区域、名单、命名方案。旧V1备份也能导入；V2备份不要交给旧V0.1代码写回。
7. 在生产入口待离线资源就绪，断网关闭再打开，核对布局与命名方案，并尝试PNG/Excel/JSON下载。

测试删除/清空前请先下载已有活动的备份，或使用独立测试浏览器资料。当前未关联远程、未推送部署；公开URL、远程CI与真实设备仍在发布阶段执行。

## 明确限制

- 场地坐标是示意，默认圆桌半径固定，不是测量工具或消防/通道规范计算。允许重叠但持续提示；越界拒绝。
- 规则为大组优先启发式，不保证全局最优。“同类”仅指手填分组，无姓名关系推断或AI。
- 区域最多100个，画布400–12000整数单位；PNG最长边4096且最多1600万像素，大图优先SVG。拖动和点击/坐标菜单均可操作。
- 方案与检查点同样受完整JSON 10MB上限约束，可显式仅备份当前数据，但历史不会被自动删除；要迁移方案应下载包含历史的完整备份。
- 不含礼金/伴手礼、账号/云同步、逐席座位、剧院式/主席台等V0.3及范围外能力。
