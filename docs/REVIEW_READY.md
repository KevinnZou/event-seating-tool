# V0.1 整体验收包

日期：2026-10-20。原始规格中的V0.1开发与本机自动化验证已收尾，现在可以按本清单一次性验收。未把后续版本方向混入本次范围；未使用旧项目私有数据，也未修改旧项目。

## 入口

- 开发：项目根目录 `npm ci` 后执行 `npm run dev`，使用终端实际端口。现有5174页面可直接刷新继续。
- 生产版：`npm run build && npm run preview -- --host 127.0.0.1 --port 4176 --base /event-seating-tool/`，打开 `http://127.0.0.1:4176/event-seating-tool/`。
- **不同端口是不同origin，名单不会共享。** 生产验收入口首次没有活动是正常现象；原5174数据不会被迁移或删除。可使用虚构演示，或通过JSON备份显式迁移。
- 首页 → 创建/演示/备份恢复；活动 → 名单、工作台、桌位详情、导入、校验、检查点；导出交付 → 文字/CSV/Excel/A4名单和桌卡；顶部 → 帮助与隐私/本地匿名反馈草稿。

离线资源仅在生产版准备，开发模式不注册Service Worker。

## 建议一次性手工验收（只用虚构数据）

先为现有名单下载JSON备份；需要测试清空时，请使用独立浏览器测试资料，不在已有名单上试清空。

1. **活动隔离**：试用虚构演示，确认录入12人、计划11、确认10、待定1、不参加1、桌数3。另建活动B，应为0人，返回演示人数不变。
2. **桌位安排**：把“示例小禾一家”安排到03桌，应为4/10席；桌位详情完整显示该组。改到66桌、撤销、重做、刷新，人数保持。锁定桌后允许查看，变更入口禁用。
3. **超员与拆分**：增加虚构7人组，尝试与4人家庭同排10人桌，必须阻止。家庭拆成1/2/1三组，总人数不变；错配份额时不能确认；可一步撤销。
4. **导入**：粘贴下方3行，预览确认后新增3组6人；同名两行保留两个ID。再试一行“示例待核一家”，应要求补人数，不能静默提交。
5. **校验与工作台**：搜索原名、拼音或首字母；过滤未安排，菜单移桌；选择整组批量移动；校验中心能定位需要处理的组。手机全过程无需拖拽。
6. **交付**：下载文字/CSV/Excel，核对当前人数、未安排和不参加记录；打印名单/桌卡预览中文正确，桌号01/03/66没有变成66张桌。A4打印关闭浏览器页眉页脚。
7. **备份恢复**：下载完整JSON，在另一份测试浏览器资料中恢复；默认新建活动且显示恢复报告，名单/桌号/人数/安排相同。不要用CSV或打印文件当恢复备份。
8. **离线与键盘**：生产入口待“离线资源已就绪”，断网关闭再打开，仍能查看/移动/导出Excel与JSON。Tab/Option+Tab进入控件、Esc关闭弹窗返回入口，查看帮助与隐私。

导入用虚构文本：

```text
示例验收家庭(4)
示例验收同名
示例验收同名
```

## 范围与已知限制

- 无账号、后端、云数据库、远程名单共享、LLM、礼金/伴手礼或逐席分座；不做剧院式、主席台。
- V0.2规则建议、命名版本差异、SVG/PNG图像导出仍按原路线只规划。V0.1使用可打印名单和桌卡交付。
- 超员策略使用安全的默认阻止；不提供绕过人数校验的隐式确认。
- 浏览器资源缓存、持久存储申请、检查点均不是外部JSON备份。清理站点数据可能同时清除应用缓存和名单。
- 无远程反馈收集：帮助页只下载用户手填草稿，需明确确认无私人信息；不自动附加名单或设备日志，不自动发送。
- 公开URL、远程CI和真机验证仍需在发布阶段执行。此包是开发完成后的整体验收入口，不能当作已经公开上线的证明。
