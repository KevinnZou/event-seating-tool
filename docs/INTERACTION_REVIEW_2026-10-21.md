# 首次使用与交互精简（2026-10-21）

本轮目标：首次使用者能沿着“录入名单 → 安排桌位 → 导出结果”完成任务，无须先理解全部功能。保留本地存储、人数口径与数据保护，全部走查使用新建虚构活动。

## 当前进度决定下一步

| 活动状态                 | 主要提示与操作                                                       |
| ------------------------ | -------------------------------------------------------------------- |
| 尚无名单                 | 导入第一份名单，或逐组添加；场地图可以稍后调整                       |
| 有计划出席宾客、尚无桌位 | 添加第一张圆桌                                                       |
| 有桌位、仍有人未安排     | 先生成排桌方案；也可进入工作台手动安排                               |
| 全部计划出席者已安排     | 提示核对待定/同名/桌位，再查看并导出名单                             |
| 所有记录均不参加         | 明确“当前没有计划出席的宾客”，不误称排桌完成；保留记录与继续添加入口 |

提示由当前数据计算，刷新后继续显示正确进度，不写入另一份任务状态，也不会自动导入、分配、拆组或删除。

## 展开层级调整

- 空白新活动隐藏空表格、三个工作区入口和空历史面板，只突出开始操作。可在“更多操作→先设置桌位”先建桌，支持先准备场地的习惯。若本次会话已有撤销/重做记录，即使回到零桌零宾客状态，也保留历史按钮。
- 顶部保留导入/导出入口，编辑活动、命名方案和规则建议收进“更多操作”。菜单支持点击外部或Escape关闭；选动作打开弹窗前将焦点移到菜单入口，弹窗关闭后可继续键盘操作。
- 名单与桌位、工作台、平面图保留，当前视图下说明各自用途，不要求初次使用者先选视图。
- 姓名搜索常驻；出席、分组、桌位和排序放到“筛选与排序”，有条件时标明已启用；清除筛选仍在外部。
- 只有实际选中仍存在的宾客组才显示批量工具，避免空工具条和已删除ID造成的0人批量栏。
- 整桌对调、历史恢复与浏览器存储申请按需展开；备份入口在有数据的工作区继续常驻。原检查点和离页保护逻辑不变。
- 校验中心保留错误/提醒数量；只有提醒时折叠，有错误默认展开。不会静默略过同名或未安排提醒。
- 场地图常驻安排/布局模式和一键整理；舞台、过道及吸附控件在“舞台、过道与吸附”内，切换调整布局会展开。没有改变过道约束、预览确认或撤销。
- 首页说明三步主流程；创建表单说明仅填名称即可开始。空活动的全0统计改为紧凑摘要，手机按两列排列。

## 验证路径

主流程测试使用两个虚构组（家庭4、夫妻2）：创建→只点击下一步导入→加桌→生成并确认建议→刷新仍显示6人已安排→真实下载CSV。整个主流程不打开高级菜单、筛选或场地配置。

独立测试验证菜单/弹窗焦点、先建桌再撤销到空状态仍能重做、筛选与清除、选中后显示批量工具、容量不足先补桌、全不参加不误报完成，以及展开历史设置后创建检查点。旧流程测试通过实际展开入口继续操作，保留原业务断言。

六配置覆盖Chromium桌面/iPhone尺寸/Pixel 7与WebKit桌面/iPhone/iPad；这些是仿真浏览器，未声称实际Safari或物理设备验收。截图位于`output/playwright/onboarding/start-*.png`与`ready-*.png`。通过`CAPTURE_ONBOARDING=1 npm run test:e2e`可重拍，只生成虚构测试场景。

本轮未变更Dexie schema、备份格式、人数算法或任何既有用户数据，未推送或部署。
