# 刷新加载问题与安全恢复（2026-10-20）

## 检查与复现

- 4176预览HTTP响应正常。检查的两个内置浏览器同源标签页仍由旧离线缓存加载V0.1，普通刷新继续返回旧版；当时未捕获控制台异常，也未稳定复现用户描述的所有“卡住”形态。
- 独立浏览器测试可复现一个确定缺陷：旧页面持有IndexedDB3连接且不释放时，新版升级4的open持续等待，旧StorageGate只有loading/ready/error三态，因此会无解释地停在检查存储。
- 另一个恢复缺陷：存储门禁或懒加载阻塞时，原更新入口位于其后，用户可能无法访问更新；重复普通刷新仍可能读取旧应用壳。

## 修复

- 监听blocked事件，说明旧标签占用并要求先保存未提交内容再关闭。等待操作仍保持，释放后自动完成升级与显示已有活动，不超时删除或重建数据库。
- versionchange时关闭本页连接并停止读写；低版本打开高版本库的VersionError显示更新说明，不再误报只有存储权限/空间问题。
- 存储加载阶段也提供离线更新状态；应用/存储加载超过10秒后显示排查与修复入口。懒加载失败的错误页同样能进入恢复页。
- `recover.html`是独立静态页面，不依赖React或应用JS块，不读取、清空或重建IndexedDB。联网获取最新Service Worker并激活后返回应用，不注销全部缓存或清空站点数据。它故意不纳入应用离线壳，以便绕过旧应用导航缓存。
