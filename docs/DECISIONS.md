# 技术与产品决策

## 边界与冲突

- 2026-10-19：仅交付 M0 + M1。PRD 为完整 V0.1；路线中 M2 的完整排桌台、M3 导入、M4 JSON 备份恢复均后置。当前浏览器数据清理会丢失，界面不提供虚假备份入口。
- 不读取或复制旧婚礼项目、默认名单、资产或归档项目；演示和测试全部另造。未发现阻塞性冲突。
- M1 的移动、出席状态、删桌服务用基本表格菜单验证；不实现 M2 搜索/拖拽/撤销等模块。

## 架构

- React + TypeScript strict + Vite；HashRouter 与生产相对 base 兼容 GitHub Pages 子路径。不自动部署或关联远程。
- Dexie 是唯一持久源，useLiveQuery 读数据。组件只能通过 service 写入；所有跨实体变更在事务中完成。
- Zod 定义领域 schema；所有统计、校验、容量判断为纯函数。桌号数字规范化去前导零但保留显示，UUID 与 label 分离。
- Tailwind + CSS token，中文系统无衬线与等宽数字；不加载远程字体/图片/脚本。局部 UI 状态使用 React，M1 没有跨区域临时状态需求，暂不引入 Zustand。
- 所有数值边界遵循 TECH：人数与容量 1–999 整数，UI 提示建议容量 1–30；默认容量10，初始桌数0。
- 超员默认阻止；M1 不开放 warn-confirm 设置。锁定桌必须先解锁才能编辑/移入/移出/删除。已排宾客改为不参加需明确确认并清空桌位；恢复出席仍需校验容量。
- 删除宾客需确认；删桌确认后整组迁回未安排；删活动输入活动名称确认，事务仅删除其自身关联数据。
- 同名宾客永不合并，仅软警告；非法引用不计为有效已排并显示完整性错误。
- 表单更新期间禁用提交；写库成功才报告已保存；查询/写入失败有明确错误，不回退 localStorage。
- 复制活动重建全部 ID/引用，单事务提交；不复制检查点。checkpoints schema 预留，M1 不创建快照。

## 设计

- 背景 #f5f7f8，白色表面，文字 #182d31，主色 #14665f，边线 #dce5e5。
- 标题28–32px，正文14–16px，圆角12px；活动行、统计横栏、桌位与宾客表格是主要组件。移动端单列与可滚动表格；移桌使用原生 select。
- Image Gen 概念仅用于设计参考，不进入运行时资源。所有 UI 由真实 HTML 控件构建。

- 2026-10-19：lint、typecheck、test（1项首页表单测试）、build 全部通过。M0 仅界面骨架；持久化服务与实际 CRUD 在 M1 连接。
- 实际安装并验证 React 19 / Vite 8 / TypeScript 6 / Vitest 5，Node 24；ESLint、Prettier、Playwright 已配置，package-lock 锁定依赖。无外部业务 API。

## M1 补充决策与结果

- 初始桌位固定用 01、02…展示；自定义/跳号桌位通过逐桌 CRUD 创建，批量桌号解析属于后续导入模块。
- 新记录序号取现有最大 orderIndex + 1，删记录后不复用序号、不意外重排。
- 复制遇到无效引用等完整性错误时拒绝，绝不把坏引用静默改成未安排。
- 启动时显式检查 IndexedDB 并等待打开完成，再渲染业务；禁止存储场景通过浏览器测试。应用级错误边界和懒加载同时保护初始化异常。
- 手机宾客表格转为逐组行布局，所有编辑/删除/移桌控件直接可见；不依赖拖拽。
- 概念图中的工作区小图仅为辅助状态，不在真实首页显示；统计改用已安排/未安排人数，不用易混淆的百分比。首页补充 M1 编辑/复制/删除与本地修改时间，隐私提示明确 M4 尚未实现。这些均源于规格要求。
- 桌位锁定会阻止该桌宾客的人工编辑，采取更保守行为，先解锁后修改。
- 不声称离线加载静态资源：本阶段未实现 Service Worker。页面已加载后 CRUD 不需要网络，IndexedDB 持久化与离线应用安装是不同能力。
- M1 质量结果：lint 0错误0警告；strict typecheck通过；31项单元/集成测试通过；6项端到端测试通过；1项生产子路径测试通过；build通过。完整记录见 ACCEPTANCE.md。
- Playwright 新版浏览器下载缓慢，本次使用已有 Chromium 缓存，通过环境变量指定可执行文件；未变更系统浏览器配置。CI 仍安装 Playwright 对应 Chromium。

## M2 排桌工作台

- 搜索支持中文、无声调拼音与首字母；按出席、分组、桌位筛选；桌号自然排序。
- 批量选择只作用于显式所选ID；全选仅选择当前筛选结果，批量容量校验在单事务内全有或全无。
- 拆分保留原组ID作为第一份，其他份originGroupId指向原组；至少两份、总人数守恒。有关联子组时禁止单独删除来源组。
- 撤销/重做最多30步内存快照，包含本页表单与排桌操作；用当前完整快照比对防止覆盖其他标签页或后续外部操作。
- 桌位排序明确保存orderIndex；对调只交换宾客，不交换桌号/容量。锁定或目标超员时阻止。
- 复用现有视觉系统，新增工作台、筛选和批量工具条。无需依赖拖拽，手机保留每组桌位菜单。
- 安装dnd-kit、pinyin-pro；为后续导入准备Papa Parse和按需加载ExcelJS。ExcelJS的uuid依赖只使用v4，经核查使用兼容CommonJS的uuid11覆盖修复中危依赖，npm audit为0；XLSX往返将在M3/M4测试。
- M2检查：lint/typecheck/tests(36)/build通过；浏览器回归结果记入后续验收。
- M2浏览器回归捕获了异步历史包装后select值被React还原的问题：现改为事件发生时同步读取目标桌，再进入异步事务；桌面/手机6项回归全部通过。

## M3 导入核心

- 文本一行一组，只有明确括号或人数列才识别家庭人数；复杂花括号注释保留备注并要求人工核对，礼份不计人数。
- CSV支持BOM、引号换行、UTF-8失败后GB18030；XLSX动态加载、选Sheet与字段映射。文件10MB、5000行、100列、10万单元格、ZIP解压32MB/2000项限制，拒绝宏/外链/加密；公式不执行，展示人工替换标记。
- 默认append，同名仅软警告；replace输入活动名且先建持久检查点。未知桌号须明确选择自动建桌或修正，不默默丢弃。
- 每条原文保留到预览；错误行须修正或明确取消勾选。提交比较预览基准快照，防止覆盖预览后产生的新数据。
- M3核心检查：lint/typecheck/tests(40)/build通过；ExcelJS独立按需chunk，尚有构建体积提示，后续优化入口分包。
- M3界面按输入、分页预览/逐行纠错、确认写入三步实现；字段映射与行预览分为独立小组件。校验中心可定位到具体宾客或桌位。
- M3界面检查：lint/typecheck/tests(40)/build通过，新增浏览器流程覆盖导入纠错、同名保留、拼音搜索、批量移桌、撤销重做与工作台菜单。

## 恢复与历史的额外边界

- 连续撤销/重做会同步相邻命令的预期快照，避免自动更新时间导致第二步误报冲突；新增连续多步测试。
- 快照指纹经Zod标准化键顺序并按ID排序，避免JSON对象键或数组遍历顺序被误认为业务变化。
- 2026-10-20：lint/typecheck/tests(51)/build通过。备份核心、报表核心新增测试覆盖完整往返，后续分别提交对应功能。

## M4 完整备份恢复

- IndexedDB schema升级为2，仅新增localMeta表记录下载时间；导出数据协议仍为schemaVersion=1，旧数据原位保留。
- 完整JSON含所有活动、桌位、宾客组、活动设置和检查点；不把下载时间当作可迁移的“已安全保存”事实恢复。
- 先校验格式/版本/唯一ID/同活动关联/人数/容量/来源链与10MB限制。默认导入为新活动，重新映射当前数据和历史检查点中的全部引用。
- 覆盖仅按备份活动ID作用，需输入“覆盖所选活动”，自动保存覆盖前检查点；其他活动ID冲突拒绝，整体事务回滚。恢复后比较活动人数统计并返回报告。
- 清空全部数据需输入完整确认词，界面提供先下载全部备份入口。删除单活动也提供直接备份入口。
- 2026-10-20：lint/typecheck/tests(51)/build通过，覆盖全量清空恢复、新活动恢复、无效备份拒绝、覆盖保护其他活动、拆分来源和检查点引用。

## M4 报表与打印

- 文字、CSV宾客明细/桌位汇总/未安排、Excel三Sheet均从同一Snapshot计算；不参加者与未安排者完整保留。
- CSV/XLSX对首个有效字符为=、+、-、@的文本加单引号防公式注入；数据库原文不变。CSV UTF-8 BOM、标准引号和换行转义；XLSX重新读回测试通过。
- 文件名过滤路径/控制字符，截长仍保留扩展名。A4名单与桌卡使用浏览器打印/PDF，重复桌标题表头，按桌防分页，奇偶桌分组，自定义桌单列。
- 工作区/首页/导出页按路由延迟加载；ExcelJS仅在读写XLSX时加载（约929KB原始/256KB gzip），其余应用chunk均小于500KB。为已知的大型可选Excel引擎设置1000KB提示阈值，不让其进入首屏资源。
- 2026-10-20：lint/typecheck/tests(53)/build通过；桌面/手机10项浏览器测试通过，含完整JSON下载-清空-恢复、CSV/Excel下载与打印CSS预览。

## M4 界面与可靠性

- 首页、工作区和交付页接通完整备份恢复；恢复报告通过路由临时状态展示，URL不包含名单。切换活动时重新挂载工作区，避免沿用上个活动的选择与弹窗。
- 工作区显示外部备份触发时间和变更提醒，离开有名单但未备份的页面时提示；本地检查点可显式创建/恢复，恢复前再建保护检查点。
- 持久存储申请仅在用户点击时调用navigator.storage.persist()，结果明确显示，不替代备份。BroadcastChannel仅广播活动ID及临时实例ID，提醒其他标签页正在查看同活动。
- 清空全部数据、恢复备份后清除内存撤销栈。备份下载只记录触发时间，不宣称用户已经保存了文件。
- UI端到端14项（桌面/手机）通过，含300人30桌、500人50桌导入/搜索/移动。性能仅代表本机Chromium测试，不冒称全部设备保障。

## M3 指定更新与最终回归

- 新增逐行“指定更新”入口：按稳定ID选择现有组，显示原人数→新人数，提示空字段也会替换；同名绝不自动选择。多行指定同一目标、跨活动目标、锁定目标全部拒绝。
- 替换全部模式不接受更新目标；选择替换时清除预览目标选择。新增/更新/排除分别报告。
- 目标下拉只在用户要求指定更新时渲染，避免500人预览时生成上万无用option。
- Repository.snapshot改为只读事务，确保统计不会读到跨提交的半新半旧快照。公式单元格保留原表达式作人工修正，不执行公式。
- 四项质量检查通过（54个单测/集成测试）；桌面拖放/手机菜单和显式更新四项新增浏览器回归通过。

## 存储失败与检查点膨胀

- 配额耗尽统一给出中文错误，本次变更不宣称保存；浏览器模拟写入QuotaExceededError验证不留下半个活动。
- 历史检查点可显式确认删除，当前名单不变；下载时可明确取消包含历史检查点，仅备份全部当前数据，避免历史快照过大阻断核心名单备份。默认仍包含全部检查点，不自动丢弃。
- 新增schema1→schema2迁移保留数据测试、跨活动恢复ID冲突回滚测试；58个单元/集成与20个桌面/手机浏览器测试通过。
- 桌号奇偶由统一纯函数按最后一位数字判断，避免超长数字桌号的浮点精度错误；自定义桌不参与奇偶。名单空筛选结果与清除入口明确显示，长桌号/组名允许换行。
